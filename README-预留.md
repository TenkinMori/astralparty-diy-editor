## 2. 数据格式约定（★ 直接沿用现有格式，不另造 ✓）

★ 关键决定：**DIY 关卡 = 现有的 `levels/*.json` + 可选的 `boards/*.json`** ✓
（服务端**本来就**按 mtime **热重载**这些文件 ✓ ⇒ 编辑器只要把文件写到"关卡\"目录，
再让服务端把它算作一个关卡即可 ✓，**不需要新的解析器** ✓。）

已确认支持的字段（来自现有实现）：

```jsonc
{
  "rounds": 99,                    // 总轮次（进度上限与之相关）
  "progress": {                    // 进度规则
    "start": 1,
    "per_round": 1,
    "per_death": 1
  },
  "progress_events": [             // ★ 进度事件（按进度阈值触发）
    {
      "at": 10,                    // 进度到 10 时触发
      "spawn": [                   // 刷怪
        { "table": 1004, "node": 27, "count": 1,
          "hp": 200, "defense": 6, "attack": 8, "gold": 12, "weight": 1 }
      ]
      // 其它效果（给星币 / 发牌 / 攻防加成）以现有实现为准，见设计核心 §2
    }
  ],
  "victory": { "targets": [1003] },// 胜利条件（例如击杀某只 Boss）
  "boss": 1067                     // BOSS（配合 boss_max_hp 等）
}
```

★ **`spawn` 已知字段**：`table`(怪表 id) / `node`(格子编号，`-1` = 随机格) / `count` / `hp` / `defense` / `attack` / `gold` / `type` / `weight`
★ **格子功能**来自棋盘文件（`boards/<后缀>.json` 的节点类型：雷劈 / 疾跑 / 商店 / 事件 / 门 …）
★ **怪物分组**（普通小怪 / 精英 / Boss）将来由编辑器维护，建议写进关卡文件的自定义键（例如 `"groups"`），
   ★ **服务端可忽略**（不影响游玩），仅编辑器与展示使用。
