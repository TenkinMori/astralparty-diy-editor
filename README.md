# 吉星派对 · DIY 关卡编辑器

> 《吉星派对》（Steam：AstralParty）的**本地关卡编辑器**：可视化编辑 DIY 关卡的棋盘、怪物、事件、开局配置，导出成游戏/私服能直接读取的 JSON。
>
> 纯本地 WPF 工具，**不联网、不需要服务端在跑**——它就是「编辑 + 存盘」。
> 服务端和客户端只是去读它写出的文件。

---

## 它和游戏/私服怎么配合

```
编辑器（WPF 单文件 exe）
   │  读写同一目录
   ▼
<游戏根>\DIY关卡\<关卡名>.json          ← 关卡配置（服务端读）
<游戏根>\DIY关卡\<关卡名>.board.json    ← 棋盘布局
   ▲
   │  按文件名加载
服务端（data/diylevels.json 里登记后，作为一档难度/关卡加载）
```

- 编辑器**不碰**游戏文件、不碰启动器、不碰服务端进程，只读写 `DIY关卡\` 目录。
- 做好的关卡交给服主登记到服务端 `data/` 后即可上线。

## 目录结构

```
astralparty-diy-editor\
├─ src\                 WPF 工程（.NET 8，C# + XAML）
├─ 棋盘缓存\             官方画板 JSON（构建时嵌入 exe，运行时可被磁盘覆盖）
├─ 贴图缓存\             官方贴图 PNG（同上）
├─ 图标缓存\             84 只怪物立绘 PNG（编辑器/导出脚本用）
├─ tools\               资源导出与侦察脚本（Python）
├─ docs\                每轮改动记录（第 1~12 步等）
├─ DIY关卡编辑器-设计稿-v2.md
├─ 森秋幻境极限-编辑器用法.md
├─ 混沌刷怪填写表.json
├─ STATUS.md            交接说明（当前状态 / 待办）
└─ README.md
```

> `棋盘缓存` / `贴图缓存` 会被 csproj 以 `EmbeddedResource` 嵌进 exe，
> 所以「只有一个 exe + 放进空目录」也能画出棋盘和图标；磁盘上有同名文件时优先用磁盘的（方便替换）。

## 构建

依赖：**.NET SDK 8.0**（Windows），WPF。

```powershell
# 调试构建
dotnet build src\DIY关卡编辑器.csproj -c Release

# 单文件发布（自包含，产物约 190MB，含内置缓存）
dotnet publish src\DIY关卡编辑器.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o dist
```

产物：`dist\DIY关卡编辑器.exe`（单文件，双击即用）。

## 使用

1. 双击 `DIY关卡编辑器.exe`
2. 首次运行在 `dist\编辑器配置.json` 里指定 `table_dir`（指向游戏配置表目录）与 `monster_art`
3. 「新建」从 `_模板\` 选模板 → 编辑棋盘/怪物/事件 → 导出
4. 导出文件写到游戏根 `DIY关卡\`，服务端登记后即可加载

详细图文步骤见 [森秋幻境极限-编辑器用法.md](森秋幻境极限-编辑器用法.md)，设计约束见
[DIY关卡编辑器-设计稿-v2.md](DIY关卡编辑器-设计稿-v2.md)。

## 已知限制

- 单文件 exe 约 190MB（内置棋盘 + 贴图缓存），首次启动略慢
- 编辑器依赖游戏配置表（`table_dir`），换游戏版本要更新配置
- DIY 关卡能否上线取决于服务端是否登记（`data/diylevels.json`）
