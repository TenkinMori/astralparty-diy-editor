* 源路径（本地已有，游戏 `GameRes` 里就躺着成品 PNG）：
  `D:\steam\steamapps\common\Astral Party\8vJXn6CN\GameRes\Img\UT_MapPreview_016.png`
* 资产名（包里那份）：`UT_MapPreview_016`（Texture2D）

* 落地：`D:\小小兔趴\5-DIY关卡\贴图缓存\UT_MapPreview_016.png`
  —— **原始字节直拷**，SHA256 与源一致（`d6f692d962d7cf6c8b9920a38fced52aabd48d8cd16d2abe2ae67fb7c86d7407`），没缩放、没裁切、没重编码。

## 1.2 判断依据（为什么笃定是它）

### 依据 A —— 游戏自己的「地图 -> 图片名」登记表（最硬）

`Map.bin` 顶层 **field 1** 就是「地图 id -> 官方图片名」注册表，其中：

| 字段 | 含义 | 示例（第一条） |
|---|---|---|
| field 8 | `MapImage` —— 选图卡片那张美术预览 | `'UT_MapPreview_003'` |
| field 9 | `MapSceneImage` —— 横版大图/载入图 | `'UT_MapScene_003'` |

把 24 条全 dump 出来（`tools\_map_images2.py`），**82016 那一行是**：

```
地图 id 82016
    3  = 820160                       <- 名字 id
    8  = 'UT_MapPreview_016'          <- ★ 就是它
    9  = 'UT_MapScene_016'
    10 = 82016
```

再把名字 id 拿 `STRMap.bin` 一翻（`tools\_map_final.py` 实测输出）：

```
地图 82016  f3=820160  名字=被异变转化的图书馆会上演什么样的表演？  f8=UT_MapPreview_016  f9=UT_MapScene_016
```

**「被异变转化的图书馆」—— 和「异变图书馆」是同一条，地图 id 也对得上 82016。**
而 `UT_MapPreview_*` / `UT_MapScene_*` 这两个名字族在**全部 157 张客户端配置表里只出现在 `Map.bin` 这一张**
（`tools\_image_name_tables.py` 实测：`Map.bin {'UT_MapPreview_': 37, 'UT_MapScene_': 37}`，其余表 0）。
所以这不是我猜的命名规律，是**游戏自己的登记**。

### 依据 B —— 反向证明 023 不存在

* `tools\_pixel_hunt.py` 的 catalog 解析：`UT_MapPreview_023 entries=0`、`UT_MapScene_023 entries=0`。
* 把 **1149 个本地 Addressables 缓存包**逐个按字节扫 `UT_MapPreview_`/`UT_MapScene_` 字面量：
  **只有 1 个包命中，就是 `cf798ba1a09c515c0f965ea491222d63`，里面是 `UT_MapPreview_016`**。
  没有任何 `023`。
* 全库 5500 个包的 Texture2D 名字总表（`tools\_tex_inv.tsv`，13,804 条记录 / 7,102 个不重名）
  里这一族只有 `003..016 + 019/020`，**没有 017/021/022/023**。

### 依据 C —— 像素内容对得上

`UT_MapPreview_016.png` 打开看：**一座木质图书馆的等距 3D 场景图** ——
两排书架、红毯、中央的树、穹顶彩窗、底座上还有「星趴」logo。
`UT_MapScene_016.png` 是同一个场景的横版内景（书架 + 长桌 + 一只戴兜帽的猫头鹰角色）。

## 1.3 ★ 本轮的认知修正（重要，会影响下一步怎么做）

上一轮工程里的假设是：

> 「官方预览是按**画板号**注册的：`82016 → UT_MapPreview_023`」

**这个假设是错的**，而且是「异变图书馆没有官方美术图」这个结论的唯一来源。实际情况：

| | 按画板号推（旧假设） | 游戏登记表（实测） |
|---|---|---|
| 82016 的画板号 | `023`（Mids -> 场景名 -> `Map_023`，这条链没错） | 同 |
| 82016 的卡片美术 | `UT_MapPreview_023`（**不存在**） | **`UT_MapPreview_016`** |
| 82016 的横版大图 | `UT_MapScene_023`（**不存在**） | **`UT_MapScene_016`** |

* **画板号（棋盘）** 与 **美术图号** 是**两套编号，会不一致**：
  * 82016 -> 画板 `023`（`Map_023` / `MiniMap_023`）／ 美术 `016`
  * 81007 -> 画板 `021`（`Map_021` / `MiniMap_007`）／ 美术 `UT_MapPreview_007` + `UT_MapScene_021`
* 所以「游戏里那张卡片总得有图」这句是对的，只是**图不叫 023，叫 016**。
  这也解释了为什么在 `023` 这个名字上怎么挖都挖不到。

# 第二节 · 「图鉴」里那套像素风怪物小人

## 2.1 结论先放

**找到了，是 `UT_AccountHeadShot_Monster_01..45`（200x200 像素画），本地客户端有实体的共 45 只，已全部抽出。**
另外同一族、同一画风的 `UT_AccountHeadShot_Boss_01..13`（13 只 BOSS）也一并抽出。

* 资产类型：`Texture2D`（不是图集里切出来的一块 —— 是**一张一图**，一张怪一个独立包）
* 资产名：`UT_AccountHeadShot_Monster_<NN>`，`NN = 01..48`（表里登记 48 个，本地有实体 45 个）
* 原始尺寸：**全部 200x200**，`m_TextureFormat = 25`（ASTC/压缩），解码后 RGBA
* 落地：`D:\小小兔趴\5-DIY关卡\贴图缓存\UT_AccountHeadShot_Monster_01.png` … `_45.png`（45 张，合计 221.3 KB）
  * ★ **UnityPy 从 Texture2D 解出来的是解码后的像素，不是磁盘上的原始压缩字节**；所以这一族是「解码即存」，PNG 由我重新编码（无损），尺寸/像素值与游戏里一致。
    第一节那张地图图因为在 `GameRes` 里本来就是 PNG，所以是**原字节直拷**，两者的"原始性"口径不同，特此说明。
* 每张的颜色数：例如 `Monster_11`（魔法茶壶）只有 **322 种颜色** —— 这正是像素画的签名（对比 `UT_MapPreview_016` 是 31,771 色）。

## 2.2 判断依据

1. **名字与配置表完全对得上。** `Monster.bin` 顶层 `field 2` 的每一行里，
   **field 19 直接写着头像资产名**：
   ```
   怪 1001  ... f19='UT_AccountHeadShot_Monster_01' ...
   怪 1002  ... f19='UT_AccountHeadShot_Monster_02' ...
   怪 1003  ... f19='UT_AccountHeadShot_Boss_01'   ...
   ```
   我用 `field 4`（名字 id）去 `STRMonster.bin` 的 `field 2` 翻中文名，80 条怪**全部命中**。
2. **画风对得上。** 见产物 `tools\_sheet_pixel_monster.png`（45 只联络表）与
   `tools\_sheet_pixel_boss.png`（BOSS 族）——
   全部是**低分辨率像素画小人**（描边、纯色块、眼睛用 1-2 像素），风格统一，和用户在「图鉴」里看到的那套一致。
3. **它就在"图鉴/头像"这个用途上。** 这一族叫 `AccountHeadShot`（账号头像），
   `Monster.bin` 把它登记为怪的"头像"，而 `GameMode.bin`、`Fashion.bin` 也会引用同一批名字 ——
   即「图鉴/展示」用的就是这张头像图。
4. **上一轮为什么漏掉：** 上一轮只扫了「怪物/地图相关」的包，而且只读 `Texture2D.m_Name`。
   这一族分散在**45 个各自独立的小包**里（每个包里就 1 张 Texture2D），包名是纯 hash，
   跟 `UT_Monster_*` 不在同一个包族里，所以按包名筛就漏了。

## 错误根因（我的锅，写清楚以免再犯）

Addressables 运行时缓存的真实层级是：

```
AssetBundles\<一级hash>\<bundle hash>\__data        ← 正确（两层）
AssetBundles\<一级hash>\__data                       ← 我上一轮查的（少一层）
```

`<一级hash>` 与 `<bundle hash>` **不是同一个值** ——
所以我拿 catalog 给的 `<bundle hash>` 去拼 `AssetBundles\<bundle hash>\__data`，路径根本不存在，
`Test-Path` 全 false，于是得出「本地包没有」。
"1149 个缓存包"这个**数字**是对的（我是用 `Get-ChildItem -Recurse -Filter __data` 数的），
但我**逐个打开**时用了浅一层的路径 —— 数字对、路径错，结论就反了。
