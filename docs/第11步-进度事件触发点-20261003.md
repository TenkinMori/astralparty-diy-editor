### ★★ 结论：**只能靠事件 id 编码**（`field4 ÷ 2`）。**没有任何独立字段**能指定触发进度。

⇒ 所以"我想让它**第 3 点进度 / 约第 3 回合**触发"这件事，唯一的路是：
**挑一条 `field4÷2 == 3` 的官方事件 id，用它去编码**。编辑器按这个做：

* 用户填 `3` → **反查 `MapEvent.bin` 里 `field4÷2 == 3` 的官方事件** → 列出来（本机 13 条：32001/32007/32022/32036/32068/32102/34005/34011/35002/35012/35032/35042/35062）→ 挑一条 → **写进配置**；
* 挑的时候**优先级**：① 官方这张图这一档登记过的（`Map.bin` 难度行 field 3，如 82016 难度 1 的 32121~32124）→ ② 还没被别的条目用过的 → ③ 都用过了就**复用**（触发点相同，允许并存）；
* **官方没有那一档 ⇒ 明说、一个字节都不改**（例：「★ 官方没有触发进度 = 15 的事件（MapEvent.bin 里 field4 ÷ 2 没有一条等于 15；官方最大的触发进度是 320840）⇒ 没改任何东西」）；
* 界面上**同时显示** `触发进度 N` ＋ `约第 N 回合`（按 `progress.per_round` 换算；**没写 per_round 就只显示进度值，不硬算**）。

### ★ 落盘字段名（都在**客户端本地**那份关卡 json 里）

```json
"diy": { "events": { "1001": { "items": [
  { "n": 1,
    "trigger_progress": 3,        // ★ 想在第几点进度触发（用户填的那个数）
    "trigger_event": 32001,       // ★ 用哪条官方事件 id 编码它（MapEvent.bin field4=6 ⇒ 6÷2=3）
    "effects": [ … ] } ] } } },
"progress_events": { "32001": { … } }   // ★ 键 = 那条官方事件 id（官方 82016_1.json 就是这个写法）
```

* `trigger_progress` / `trigger_event` 写在 `diy.events.<事件id>.items[]` 的**那一行**上（一个条目 = 一条进度事件）。
* 服务端真读的那份 `progress_events` 的**键**：设了触发点 ⇒ 用**官方事件 id**；没设 ⇒ 照旧用**条目编号 n**（**老文件逐字节不变**，第 8 步那套一点没动）。
* 没设触发点时**不写这两个键**（别留空键骗人）。

   （用户要求"没设就只显示进度值，别硬算"）。**每回合 +N 目前界面上没有编辑入口**（第 8 步的四块里没有它）—— 要不要加，**等他定**。
