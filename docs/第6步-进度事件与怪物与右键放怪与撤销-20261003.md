★ **两张"右键菜单 / 下拉框"为什么是平铺的**：WPF 的 `ContextMenu` 与 `ComboBox` 下拉列表都活在
`Popup`（另一棵视觉树）里，`RenderTargetBitmap` **渲不到**。所以加了只给截图用的平铺区，
用的是**同一份数据**（同一个 `BuildPlaceMonsterMenu` 的怪清单 / `Land.PickIds` 的结果），
真人用时它们 `Collapsed`，一个像素都不占。

★ **顺手修掉的一个真 bug（用户当场看出来的）**：_截图\页3 上一版里，下拉框"选中项"的文字是**黑的**。
根因：`Drop` 模板把 `SelectionBoxItem`（= **选中项本身**）喂给一个裸的 `ContentPresenter`，
而模板上的 `Foreground` **只对纯字符串项生效** —— 我一开始用 `ComboBoxItem` 塞项，
它自带系统模板 ⇒ 黑字；同一个下拉框的"展开箭头"却是亮的，看着就像"只有值是黑的"。
修法：**所有代码里的下拉项一律塞"实现 `ToString()` 的值对象"**（`PageStory.Pick` / 纯字符串），
`App.xaml` 的 `Drop` 注释里把这条写成铁律，自测 **⑫v** 从源码上盯着
（`Items.Add(new ComboBoxItem` 出现即失败）。

```jsonc
{
  "map": 82016,
  "difficulty": 1,

  // ① 你那份清单（权威：保序、可重复；服务端现在不读）
  "diy": {
    "events": {
      "32124": {
        "effects": [
          { "type": "gold",            "n": 10 },
          { "type": "monster_attack",  "n": 1 },
          { "type": "spawn",           "table": 1069, "node": 17, "count": 2 },
          { "type": "spawn",           "table": 1070, "node": -1, "count": 1, "hp": 33 },
          { "type": "mutator",         "mutator": 60008 }
        ]
      }
    }
  },

  // ② 服务端真读的那份 —— 由 ①**同步**出来（不是各填一遍）
  "progress_events": {
    "32124": {
      "spawn": [
        { "table": 1069, "node": 17, "count": 2 },          // 没写 hp ⇒ 回落 Monster.bin
        { "table": 1070, "node": -1, "count": 1, "hp": 33 } // 写了 hp ⇒ 就用 33
      ],
      "attack": 1
    }
  },

  // ③ 第④页"开局就在场上"那台来源（缺字段**补 0**，所以六个数值都显式写出来）
  "start_monsters": [
    { "table": 1067, "node": 29, "hp": 10, "gold": 6, "defense": 0, "attack": 0, "type": 10, "weight": 60 }
  ]
}
```

★ 六种条目类型与落点（`type` 就是写进 json 的字符串）：

| `type` | 界面上的名字 | 参数 | 落哪 | 服务端现在读不读 |
|---|---|---|---|---|
| `gold` | 所有玩家 +N 星币 | `n` | 只 `diy.events` | ✗（官方效果表 1~6 号里没有这一种） |
| `card` | 所有玩家获得某张牌 | `card` | 只 `diy.events` | ✗（官方有 4 号 `GainCard`，服务端还没做） |
| `monster_attack` | 怪物攻击力 +N | `n` | 也同步进 `progress_events.<id>.attack` | ✓ |
| `monster_defense` | 怪物防御力 +N | `n` | 也同步进 `progress_events.<id>.defense` | ✓ |
| `spawn` | 怪物出场（spawn 刷怪） | `table` / `node` / `count` / 可选 `hp` `gold` `defense` `attack` `type` `weight` | 也同步进 `progress_events.<id>.spawn[]` | ✓ |
| `mutator` | 词条（Mutator） | `mutator` | 只 `diy.events` | ✗（官方"词条PVE"用的是 `Mutator.bin`，但官方关卡 json 里没有词条的位置） |

★ 两条**同步规则**（`DiyEventEffects.Sync`，自测 ⑫h/⑫i/⑫j 盯着）：
1. 同一事件里**怪物攻 / 防各只同步第一条**（服务端那两个键就是一个整数）；重复的那些**仍留在 diy 清单里**，界面上灰字写明"这条不会进 progress_events"。
2. 一个 `spawn` 条目都没有 ⇒ **把 `spawn` 键摘掉**，不留 `"spawn": []` 这种骗人的空数组；整行空了就把 `progress_events.<id>` 也摘掉。

| `progress_events.<事件id>.attack` | 场上所有怪 攻击 +N（官方 3 号 `MonsterAttrChange`） | 第③页 `monster_attack` 条目（同类只同步第一条） |
| `progress_events.<事件id>.defense` | 场上所有怪 防御 +N（同上） | 第③页 `monster_defense` 条目 |
| `progress_events.<事件id>.move` | 额外移动 | ★ 编辑器**不碰**这个键（不写也不删） |
| `start_monsters[]` | 开局就在场上的怪（`table` 必填；**缺字段补 0**） | 第④页 / 棋盘右键放怪（默认放到"开局就在场上"） |

### 5.2 编辑器已经落盘、**服务端要按这份形状实现才生效**的

| 键 | 含义 | 建议服务端怎么读 |
|---|---|---|
| `diy.events.<事件id>.effects[]` | 用户那份效果清单（保序、可重复） | 按 `type` 分派：`gold` → 给所有玩家 `n` 星币；`card` → 给所有玩家卡牌 `card`；`mutator` → 把词条 `mutator` 挂进这一局（官方"词条PVE"那套）；`monster_attack` / `monster_defense` / `spawn` **与 `progress_events` 那份等价**（两份由编辑器同步，读哪份都行） |
| `diy.progress_limit` | 总进度上限（覆盖官方难度行的 `ProgressLimit`） | 有它就用它，没有回落难度行（**上一批就在等这一条**） |
| `diy.starts` | 起点 1~4 分别是哪一格（按序） | 有它就用它，没有按起点格 `serial` |
| `diy.base_map` / `diy.base_scene` / `diy.base_level` / `diy.base_level_sha256` / `diy.board` / `diy.name` / `diy.version` / `diy.created` | 这份 DIY 的身份与底版来源 | 只是想"认得出一份 DIY 关卡是从哪张官方图改的" |

## ⑥ 没做到 / 不确定

1. ★★ **"哪些效果类型官方确实支持"—— 只有三种真的会生效**：`monster_attack` / `monster_defense` / `spawn`
   （对应官方 3 号与 1/2/6 号效果，`battle.progress_event_effects` 里有分支）。
   另外三种（`gold` / `card` / `mutator`）**官方关卡 json 里根本没有它们的位置**：
   * `card`：官方有 4 号 `GainCard`，但服务端那个分支**还没做**（`battle.py:1246` 的注释自己写着"还没做"）；
   * `gold`：官方效果表 1~6 号里**没有**"发星币"这一种；
   * `mutator`：官方"词条PVE"（模式 12 畸变组件）用的**确实是** `Mutator.bin` 这张表
     （名字 `STRMutator`、图标 `UT_Mutator_<id>`、25 张图标），但**只按"难度行 field 8 = MutatorPool"整局给**，
     没有"某个进度事件发一个词条"这种粒度 ⇒ 我落 `diy.events`，**服务端将来要读才生效**。
   ★ 所以：**想让效果立刻生效，就用 `怪物攻击力/防御力/怪物出场` 这三种**；另外三种现在只是"先记下来"。
2. ★ **星币数值只能是整数**（`n`），没有"按百分比"、"给某个玩家"、"给道具/遗物"这几类。
   官方效果表里也没有这几类（1~6 号全在 `MapEventEffectType` 里列完了）⇒ 我没有发明新类型。
3. ★ **同一事件里怪物攻 / 防各只同步第一条进 `progress_events`**：服务端那两个键就是一个整数。
   重复的条目仍在 `diy.events` 清单里（界面上灰字写明）。想要"叠加"就得改服务端。
4. ★ **`spawn` 的可选覆盖字段界面只给了"血 / 防"两个框**：`gold` / `attack` / `type` / `weight`
   在**数据形状与同步里都支持**（`EventEffect` 有这六个字段、`Sync` 也写），但第③页那行没排下那么多框
   ⇒ 现在只能在其它四个上改（免得挤成一团）。要的话下一批补 `攻击 / 币 / type / 权重` 四个小框。
5. ★ **编辑器不校验"事件 id 跟这张图对不对"**：只要 `MapEvent.bin` 里有这个号就允许加；
   不在表里的号会**红字提醒**"不在 MapEvent.bin 里（官方没有这个号）"，但**不拦**。
6. ★ **`start_monsters` 缺字段"补 0"这件事，编辑器是把 0 显式写出来的**（服务端本来就补 0）。
   如果服务端以后改成"回落表"，那这些 0 就会顶掉回落值 ⇒ 那时要一起改。
7. ★ **撤销栈的上限 60 步**（`UndoStack.Max`），编辑快照是"整份 json 的字节"（几十 KB / 步）
   ⇒ 极端情况下占用约几 MB，可接受但不是零成本。
8. ★ **`Reload()` 会把视图重置成"适应窗口"**（沿用第 4 批的行为）⇒ 撤销一个**编辑动作**之后，
   视图回到适应窗口的样子（不是"你撤销前的缩放"）。这是沿用旧行为，没改。
9. ★ **右键菜单里每一类最多列 14 只**（`PlaceMenuPerClass`），超过的部分走「手填怪表 id 放一只…」。
   `Monster.bin` 一共 80 只（普通 21 / 首领 24 / 精英 35），全列出来菜单会长得没法看。
10. ★ **第④页右侧只能编一只**（点卡片切换）；批量改（多选一起改属性）没做。
11. ★ **`.ps1` 这一批一个都没写**；`.cs` / `.xaml` 全程用编辑工具改，没有用 PowerShell 过文本。
