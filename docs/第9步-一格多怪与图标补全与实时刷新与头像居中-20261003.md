### ③-① 一格多只怪

**数据结构**（复用第 8 步定的那份，**没有改形状**）：

```json
"diy": {
  "monsters":        [ { "id": 1, "table": 1001, "hp": 6, ... }, ... ],
  "board_monsters":  [ { "node": 5, "pool": 1 },
                       { "node": 5, "pool": 2 },     // ★ 同一格第二条
                       { "node": 5, "pool": 3 },     // ★ 第三条
                       { "node": 5, "pool": 1 },     // ★ 同一只再放一次也允许
                       { "node": 9, "pool": 1 } ]
}
```

`board_monsters[]` 本来就是数组，**同一 node 多条**读写的这条路一直是通的（第 8 步 §⑥.3 就写明了"数据结构是数组"）——
这一批做的是**把界面开放**：以前右键放怪走 `PlaceAt`（先清空这一格再放，所以再放就顶掉原来那只），现在走 `AddAt`（**追加**）。

**叠放 / 角标规则**（`MonsterStack`，自测 ⑬e/⑬f/⑬g 逐条盯）：

| 这一格几只 | 画面 |
|---|---|
| 1 只 | 头像直径 = 格子边长 × **0.62**，**正正好居中于格子的内容层**（偏差 0） |
| 2 只 | 直径 ×0.54，沿 **45°**（右上 / 左下）各偏 **半步**（步长 = 直径 × 0.42） |
| 3 只 | 直径 ×0.48，沿 45° 偏 **−1 / 0 / +1 步**（中间那只正好在格子中心） |
| ≥ 4 只 | 只画 **3** 个（同样以格子中心对称），**右下角**贴一个红底白字 **「+N」** 角标，N = 没画出来的只数；悬停给"这一格一共 M 只" |

> 角标为什么在**右下角**而不是右上角：右上角是"显示编号"的编号徽标、正上方是错开叠放的头像，
> 右下角是唯一不打架的位置。

**右键怎么列出多只**（`PageBoard.BuildCellMenu`）：

```
新增怪物（这一格现在 4 只 ⇒ 再追加一只）     ← 永远第一项，点了弹同一个二级窗口，选完**追加**
────────────────────────────
这一格上的怪（4 只，点就是拿掉这一只）      ← 灰色标题行（不能点）
拿掉 1/4  #1 1001 小偷
拿掉 2/4  #2 1002 海盗鲨鱼
拿掉 3/4  #3 1003 嘎呜
拿掉 4/4  #1 1001 小偷                     ← 同款放两只时能只拿掉其中一条
────────────────────────────
还原原版
```

★ **删掉某只怪时，池子里没被任何格引用的那条一并清掉吗？** ⇒ **不清**（与用户规格一致）：
`RemoveOneFromNode` 只摘棋盘上那一条引用，`DiyPool` 里的那条原样留着，
由**怪物页的「未配置」那一栏**显示、由**校验②「有怪物未配置进度」逐只点名**。
（想彻底拿掉要去怪物页按「从池子里拿掉」——那才是一条命令同时清棋盘/条词/获胜条件。）

**副作用面**：
- 右侧「格子」那块会逐只列出（`★ 这一格有 N 只怪：1. … 2. …`）+ 提示"右键能逐只拿掉"；

### ③-③ 实时刷新（这是个 bug）

**病根**：`PoolMonster.ProgressN`（一只怪挂在哪条进度下 = 怪物页分栏的依据）**只在 `DiyPool.Read()` 里算一次**。
而界面上的编辑是**在内存对象上原地改**的（`SaveDiy` 刻意不换对象，第 8 步定的规矩）——
于是"在进度页给某只怪加了「新增怪物」条词"之后，`ProgressN` **还是旧账**，
怪物页就一直把它摆在「未配置」栏 ⇒ 用户看到的就是**"我在事件那边配置了还是没显示"**。

**改法**（两条一起）：

1. **派生字段当场重算**：`LevelDoc.SaveDiy(d)` 写完树之后立刻 `DiyPool.BindProgress(d)`
   （先全清空、再按编号最小的那条重新挂）；`PageMonsters.Reload()` 开头也再算一次兜底。
2. **变更广播 + 各页对版本号自己重建**：新增 `DiyNotify`（`Version` + `Changed`）。
   `DiyNotify.Touch()` 在每次 `SaveDiy` 末尾响一声；页面 `IsVisibleChanged` 时对版本号，对不上就 `Reload()`。

### ③-④ 棋盘上怪物头像偏移

**两处原因，两处都修**：

1. **位置**（主因）：原来画头像那一段是
   ```csharp
   Canvas.SetLeft(frame, pp.X - d / 2);
   Canvas.SetTop (frame, pp.Y + half - d * 0.62);   // ★ 偏到格子下缘去了
   ```
   `half = node/2`、`d = node*0.62` ⇒ 头像顶边被压到"格子中心往下 0.116×格子"，
   整只头像的**中心**跑到格子中心下方 `0.43 × 格子边长` —— 直接偏出格子。
   ⇒ 改成 `MonsterStack.Rect(...)`：**参考系 = 格子的内容层**（格子自己摆在 `p − node/2`，
   所以格子的内容层中心就是 `p`），`left = p.X − size/2`、`top = p.Y − size/2`。
   ★ 这正是第 7 批说过的"参考系必须是内容那一层"——这一类 bug 的老毛病就是加到了外层。
2. **图像**（同源问题，用户让查的）：官方怪头像是宽幅半身像、**角色不居中**（56/63 张偏 > 8 px）。
   ⇒ 新增 `Art.CenteredSquare()`：先量"不透明内容"的外接框，再按它**居中裁成正方形**，
   圆里塞的就是这一块 ⇒ 角色一定在正中央。

**四档格子大小都验过了**：`PageBoard.NodeRatioOptions` = 45% / 60% / 72% / 85%，
每档再配 4 个缩放（格距 40 / 80 / 140 / 200 px），**共 16 组**，1 只怪时"头像中心 − 格子中心"误差 **0**（自测 ⑬e）。
另外在**真渲染那一层**也量过一遍（`PageBoard.LastPlacement` 打屏，见 §⑥.6）：

```

格 1 第 2/4 只（#2 1002 海盗鲨鱼）中心(105.6,494.6) 格子中心(105.6,494.6)  偏差 0.00

格 0 第 1/2 只（#2 1002 海盗鲨鱼）中心(101.7,554.9) 格子中心(105.6,551.0)  偏差 5.48
```
