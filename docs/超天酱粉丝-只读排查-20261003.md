## ③ 根因（引用原文）

`skills.py:820-829` —— **没有目标选择、没有距离、没有只数上限**：

```python
    new_fans = 0
    for monster in battle.monsters(room):          # ★ 遍历**场上每一只怪**
        monster_id = int(monster["id"])
        if int(monster.get("hp", 0) or 0) <= 0:
            continue                                # 只跳过已倒地
        if buffs.layers(room, monster_id, ANGEL_FAN_BUFF) > 0:
            continue                                # 只跳过已经是粉丝的
        new_fans += 1
        grant_buff(room, caster, monster_id, [ANGEL_FAN_BUFF], out, skill["id"],
                   count=1)
```

★ 唯一的"上限"是 `min(cap, base + new_fans)`（`skills.py:832`）—— 那限的是
**拿多少星币（cap=10）**，**不是"最多把几只怪变粉丝"**。
所以场上只要有 14 只活怪，它就把 14 只全变成粉丝，星币照样只给 10。

## ⑥ 那么"正确行为"到底是什么？—— 需要用户拍板，我给三个方向

★ **代码和表都不支持"只变一只"**。所以这不是"改回来"，是"要什么口径"：

1. **就是全场**（当前行为）—— 那用户看到的"全变粉丝"是设计如此，
   要改的只是**观感/平衡**，不是代码。
2. **按文案字面**：文案（STRSkill 301030，`skills.py:801-804`）只说
   「每使得一个怪物成为【粉丝】，额外获得 1 星币，一次技能最多获得 **10** 星币」。
   如果用户认为"最多 10 星币"隐含**最多 10 只**，那就在 `run_angel` 的循环里
   加一个 `if new_fans >= cap: break` —— **一行**，而且和文案不冲突。
   ★ 但这是**新口径**，不是"修 bug"（回放里 14 只都变过粉丝，说明官方没这个限制）。
3. **按距离/范围**：★ 表里**没有**范围字段 ⇒ 只能自己定一个（比如"离超天酱 N 格内"）。
   这会**偏离官方**，属于 DIY 玩法改动，要单独立项。

★ 我**不替用户选**。要定的话，需要他说一句"应该只变几只 / 什么范围内的"。
